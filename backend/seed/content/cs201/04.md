## Restricting access on purpose

Stacks and queues are lists with deliberately limited interfaces. You may only add and remove elements at specific ends. That restriction sounds like a loss, but it makes the structures easy to reason about and lets every operation run in constant time.

## Stacks

A **stack** follows the last-in, first-out rule, usually shortened to **LIFO**. Think of a stack of plates: you add to the top and take from the top. The operations are:

- `push(x)`: place *x* on top.
- `pop()`: remove and return the top element.
- `peek()`: return the top element without removing it.
- `is_empty()`: report whether the stack has anything in it.

A dynamic array implements a stack naturally. The end of the array is the top, so push is an append and pop removes the last element. Both are O(1), amortized for push. A singly linked list works too if you treat the head as the top.

Stacks appear wherever work must be undone or resumed in reverse order. Your programming language keeps a **call stack**: each function call pushes a frame holding its local variables, and returning pops it. The undo history in a text editor is a stack of edits. Depth-first search uses a stack, explicitly or through recursion, to remember which branches it still has to explore.

## Example: balanced brackets

Suppose you need to check whether a string like `{[()()]}` has properly matched brackets. Scan from left to right. When you see an opening bracket, push it. When you see a closing bracket, the stack's top must be the matching opener; if it is, pop it, and if it is not, or the stack is empty, the string is unbalanced. At the end, the string is balanced only if the stack is empty.

This works because brackets nest. The most recently opened bracket must be the first one closed, which is exactly the LIFO rule. The algorithm reads each character once, so it runs in O(n) time and uses at most O(n) extra space.

## Queues

A **queue** follows first-in, first-out, or **FIFO**. Like a line at a coffee shop, people join at the back and are served from the front. The operations are `enqueue(x)` to add at the back and `dequeue()` to remove from the front.

A plain dynamic array is a poor queue. Removing the first element forces every other element to shift left, which costs O(n). Two better options exist:

1. A **linked list** with head and tail pointers. Enqueue appends at the tail and dequeue removes the head, both in O(1).
2. A **circular buffer**: an array with two indices, `front` and `back`, that wrap around to zero when they reach the end. Dequeue just advances `front`; nothing moves. When the buffer fills, allocate a larger array and copy the elements in order, as a dynamic array does.

The circular buffer is usually faster because it keeps elements contiguous. It is how most standard library queues and the network buffers inside operating systems are built.

Queues model anything processed in arrival order: print jobs, requests to a web server, messages between programs. Breadth-first search uses a queue to visit a graph level by level, which is why it finds the shortest path in an unweighted graph.

## Deques and priority queues

A **deque** (double-ended queue) allows adding and removing at both ends in O(1). It can act as a stack or a queue, and it is useful for sliding-window problems where elements enter on one side and leave on the other.

A **priority queue** looks like a queue but removes the element with the highest priority rather than the oldest one. It is not built from a list at all; the usual implementation is a heap, which you will meet in a later chapter.

## Choosing between them

Ask what order the work must come out in. If the newest item should be handled first, as with nested structure or backtracking, use a stack. If items should be handled in arrival order, as with scheduling or level-by-level exploration, use a queue. Writing that decision down early prevents a surprisingly common class of bugs where the right items are processed in the wrong order.
