## Relationships, not just items

Trees model hierarchies, but many relationships form webs instead. Friends know each other in tangled circles, roads connect cities in loops, and web pages link back and forth. A **graph** describes any set of items, called **vertices**, joined by connections, called **edges**.

Edges can be **directed**, like a one-way street or a follower on social media, or **undirected**, like a two-way road. They can also carry a **weight**, such as a distance or a cost. A **path** is a sequence of vertices joined by edges, and a **cycle** is a path that returns to its start. A graph with no cycles that is connected is exactly a tree, so trees are a special case of graphs.

## Two representations

An **adjacency matrix** is a V × V table where entry (u, v) records whether there is an edge from u to v, or its weight. Checking whether a specific edge exists takes O(1). The cost is memory: the matrix always uses O(V²) space, even if the graph has few edges.

An **adjacency list** stores, for each vertex, a list of its neighbours. It uses O(V + E) space, where E is the number of edges. Iterating over a vertex's neighbours is efficient because you only touch real edges. Most real graphs are **sparse**, meaning E is much smaller than V², so adjacency lists are the usual choice. A road network has millions of intersections, but each one connects to only a handful of others.

## Breadth-first search

**Breadth-first search** (BFS) explores a graph in rings around a starting vertex. Put the start in a queue and mark it visited. Repeatedly remove a vertex from the front of the queue and add each unvisited neighbour to the back, marking it visited as you go. Vertices one edge away are processed before vertices two edges away, and so on.

Because of that ring-by-ring order, BFS finds the **shortest path in an unweighted graph**: the first time it reaches a vertex is along a path with the fewest edges. Recording each vertex's predecessor lets you reconstruct that path afterwards. BFS visits every vertex and edge at most once, so it runs in O(V + E) time.

## Depth-first search

**Depth-first search** (DFS) follows one path as far as it can before backing up. It can be written recursively, visiting a vertex and then calling itself on each unvisited neighbour, or iteratively with an explicit stack. It also runs in O(V + E).

DFS does not find shortest paths, but it is the right tool for questions about structure. It can detect cycles: in a directed graph, reaching a vertex that is still on the current path means there is a cycle. It can find connected components by starting a new search from every vertex not yet visited. And it produces a **topological order** of a directed acyclic graph, listing vertices so that every edge points forward. Build systems and course prerequisite planners rely on topological order: you cannot take a course before the courses it depends on.

## Weighted shortest paths

When edges have weights, the path with the fewest edges is not necessarily the cheapest. **Dijkstra's algorithm** handles non-negative weights. It keeps a tentative distance for every vertex, starting at zero for the source and infinity for everything else, and a priority queue of vertices ordered by that distance.

At each step it removes the closest vertex not yet finalized. Because all weights are non-negative, no later route can make that vertex any closer, so its distance is now final. The algorithm then **relaxes** each outgoing edge: if going through the current vertex gives a neighbour a shorter distance than it had, update the neighbour's distance and its position in the queue. With a binary heap the total running time is O((V + E) log V).

Dijkstra's algorithm fails if some weights are negative, because a later negative edge could undercut a distance already marked final. The Bellman-Ford algorithm handles negative weights at a higher cost and can also detect negative cycles, where no shortest path exists at all.

## Choosing a traversal

Use BFS when you care about the fewest steps, such as degrees of separation between two people. Use DFS when you care about reachability, cycles or ordering, such as checking whether prerequisites form a loop. Use Dijkstra's algorithm when edges have non-negative costs and you want the cheapest route, which is how navigation apps start their search.
